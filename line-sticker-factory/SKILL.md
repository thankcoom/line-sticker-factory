# LINE 貼圖製作總監

把使用者的角色與用途轉成動作有區別、台詞正確、可交付的套組。工具隨本技能封裝，不依賴原開發專案。把本文所在目錄當作 SKILL_ROOT；作品存到使用者工作目錄，勿寫入技能目錄。

## 開始與接續

第一次使用、沒有角色、需要從多個角色選擇或跨對話接續時，先讀 [對話入口與角色建立](references/conversation-entry.md)。以少量逐輪選項引導：無 IP 先討論、生成候選並確認角色；有 IP 選擇自己的原圖；角色確認後才進入貼圖劇本與製作。具備選項工具才顯示互動選項，否則使用編號文字。一般 ChatGPT 讀到檔案不代表已永久安裝或可操作本機。

使用本人的既有 IP 時，先讀 [角色索引](references/ip-catalog.json)。索引中的 awaiting_original_export 表示只有盤點紀錄、尚未取得原圖，不可憑名稱或縮圖重建角色；先取得系統匯出的原始角色資料再製作。角色身分素材與作品分開保存，保留來源與原名。

先分清產品：靜態貼圖讀 [加工與檔案契約](references/workflow.md)，用隨附 CLI 的 status 接續；不要直接改 project.json。靜態表情貼與主題讀 [表情貼與主題](references/emoji-theme.md)，以獨立素材清單與產品規格製作，不能套用貼圖 CLI。CLI 目前只實作靜態貼圖；另外兩類是代理執行的製作與驗收流程，不是假稱已有自動加工子命令。貼圖製作只問缺少的資料，最多三組：用途／語氣、畫風／參考、張數／文字策略；新人引導依對話入口逐輪處理，不一次問完。缺角色時提供從零設計或附圖入口，不以一句補圖要求結束。角色身分圖和畫風圖分開記錄，不能用畫風圖替換角色。測試素材不代表使用者正式 IP。

沿用已知需求；未指定時預設繁中靜態 40 張、每批規劃 8 張，第一批先完成獨立 8 張驗收。文字預設與角色情境整體生成；要求逐字可編輯才改用無字圖加文字層。使用者指定無字時保留無字。已完成作品只做所需修改，不重新製作整套。

## 生成

讀 [生成與恢復](references/generation.md) 與 [畫布檢驗與局部修正](references/visual-qa.md)。先確認當次可用的生圖工具與實際參數，優先對話內建生圖。以完整角色參考、繁中台詞、動作與裝飾共同設計；文字不要統一放在角色下方。要求真透明背景、字與道具不跨格，依實際解析度裁切。

一次派送一項生成任務；記錄來源、完整提示詞、角色／風格參考、預計 slot、真實結果與狀態。工具僅回聊天預覽而無可取得檔案時記 awaiting_asset；說明須匯入原圖，不搜尋猜測圖片快取。檔案可解碼才算取得。額度不足或結果不明時保存進度並停止新派送，重試前先核對已有結果。不得默默改成付費 API，也不索取登入 cookie/token。

## 加工與驗收

- 含字原圖以 --image-contains-caption 與 --expected-caption 匯入；停用再次疊字。含字圖片改字必須重生／視覺編輯並匯入新來源，或換不同無字圖後配字。保留歷史原圖。
- 可編輯文字從乾淨來源 render；字型缺字就停止並明確回報。套件不附未授權字型。
- 預設保留 alpha；只有已知背景色才做邊界連通去背，不對白色角色盲目去白底。
- 每張畫布生成後先依 visual-qa 做一輪逐格檢驗，記錄問題與修正範圍；通過畫布檢驗後才裁切加工。使用者指定 8 格畫布時，修正以該畫布為目標並保留其餘格，不能自行換成單張重生或改掉已接受的情境。
- 必須實際查看 preview 和最終尺寸個別圖，逐字核對繁中、角色、肢體、裁切、透明邊緣、白／深底、可讀性及套組差異。通過才逐張 review pass；問題標 rework 並重做。技術檢查不能代替視覺驗收。
- 8 張首批獨立專案驗收後，40 張專案仍使用固定 01–40 編號，將同一批已驗證原圖綁定前 8 張並重新檢查該專案的加工結果。不要修改 target/count 或製作重複 slot 來擴充。

## 交付與上傳

每套上架前主動執行 [上架前檢查與退回修正](references/release-preflight.md)，保存本次版本的技術、逐張視覺、文字、標籤與平台讀回證據；問題先修好再提交，不等使用者驗出。退回原因只依通知確認，通用範例不當作定論。主題製作／研究另讀 [主題美術系統](references/theme-art-direction.md)，先定配色、場景、圖示與選取狀態，再驗完整介面。每套主題主動執行 [主題送審關卡](references/theme-release-checks.md)：橫向背景、壓縮後膚色、深底圖示與當次送審勾選項都要有最新版證據，問題先修好再提交；預設取消額外優惠通知。

靜態貼圖 build 只接受目前版本的全部驗收；8 張 ZIP 為 10 個根目錄 PNG，40 張為 42 個。表情貼／主題依各自契約驗證與打包。三類均交付真實版本化路徑：line-upload.zip、contact-sheet.png、project-backup.zip；總覽可用已驗收的主題裝置預覽。改字後舊包不再是最新交付。備份還原到新目錄，核對每張成品 hash，不覆寫原作品。

使用者要求上傳時才讀 [ego 上傳流程](references/line-upload.md) 並操作。技能呼叫本身不等於送審／販售授權；沿用本次工作已明確授權的階段，不重複詢問。取得真實作品 ID 與圖片配對證據才稱已上傳。草稿、送審、核准、公開販售分別記錄。

最終用簡短繁中說明完成張數、可點擊的三項檔案、實際驗證和未完成階段。技能提供製作流程，不提供額外生圖額度，也不保證 LINE 審核通過。
