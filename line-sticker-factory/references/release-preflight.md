# 每套上架前檢查與退回修正

每次製作、續作、補標籤或重新送審都由代理主動執行本檢查，不等使用者指出問題。這是代理看圖、工具檢查與平台讀回的流程；不是已實作的全自動圖像判錯器，也不保證審核通過。未查看、證據缺少、結果不明一律 pending，不用預設 pass。

## 檢查紀錄與送審關卡

在作品旁保存 `release-preflight.json`：

- `productId / productType / revision / checkedAt`：真實作品與本次版本。
- `technical`：檔案清單、規格、alpha、當前包 hash；使用現有 validate，不能以技術通過代替看圖。
- `visual`：逐張來源／成品 hash、台詞、角色眼型與肢體、道具來源、最終尺寸白／深底、判斷與證據；依 visual-qa。主題改依 theme-art-direction 的整套畫面驗收。
- `content`：標題、所有語言說明、AI 聲明、版權與角色來源、內容疑點；把確定錯誤與推測風險分開。
- `tags`：主題後台若未提供標籤欄位，記 `not_applicable`、原因及當次欄位檢查證據，不虛構標籤。提供標籤的產品記每個 slot 預定與重新讀回的 ID、名稱；本次未改標籤則記 `unchanged` 及原因，仍核對是否與修圖矛盾。不是每套都必須補滿相同個數。
- `remoteMapping`：每張平台 URL、已取得原始 bytes 的 hash，或必要時 RGBA 像素比對。
- `submission`：使用者本次授權範圍、價格、活動、販售地區、手動／自動開始販售、手動／自動更新、平台實際狀態與證據。
- `blockers`：未修錯字、肢體／角色漂移、缺圖、標籤不符／未保存、來源不明的必要素材、未驗收最新版等。

只有本次有變更或必要檢查均完成、blockers 為空，且已有送審授權，才提交。可先上傳既有草稿檢查平台預覽，但標為 draft-preview；不能把它當正式通過。變更素材後，對應驗收及包失效，重新看圖再提交。使用者已授權的送審流程不重複要求批准。

主題另外填寫 [主題送審關卡](theme-release-checks.md) 的 `themeChecks`；技術與視覺關卡先完成，當次確認視窗中的必要同意及優惠通知狀態在最後 OK 前讀回。任一必要項 pending／rework 都不得提交。

## 退回案件的最小修正

1. 保存通知原文、時間與作品 ID。通知若只列通用範例且註明未必適用，`confirmedReason` 記 unknown；不得直接宣稱侵權、色情或某一張就是退回原因。
2. 逐張記錄 `observation / possibleRisk / action / evidence`。優先處理錯字、明顯血泊／大量噴血等可能令人不適的內容，以及來源未確認的配角、立牌、螢幕肖像或標誌；非所有誇張表情都要刪除。不因追星、愛心眼或臉紅就推定違規。
3. 區分角色本人的身分參考與畫中道具。來源未明的人物可在授權修改範圍內換成自有 IP 道具；不能憑外觀識別或猜測授權。純粹來源不明不等於已證明侵權。
4. 只重做需要修改的格／圖。原為八格畫布時仍依原畫布局部修正；原本是獨立 PNG 時可只改該 PNG。保存舊圖、生成提示、工具回傳確切路徑與新圖。
5. 逐張對照修正前後並看最終尺寸。未改的圖片與 main/tab 若不用更新，直接保留原檔，不為打包而全部重繪；比對證據應能證明只改指定位置。
6. 文字也檢查所有語言：修正實際錯字、無關的預設英文名稱／介紹。補充說明只寫本次已完成的修正，不虛構授權證明或已查明的退件原因。
7. 在原作品替換、重新載入，從平台下載修正版比對 hash；CDN 重編碼才進一步做所有 RGBA 通道逐像素比較。圖片存在或尺寸相同都不是配對證據。

### 既有作品只換少數圖片時的封裝

現有 CLI 的 build 會加工並衍生支援圖，不能假設其輸出與既有 main/tab 相同。局部修正採逐張上傳；另在新的版本目錄建立 `remote-final/`，將平台已驗證的未改 PNG 原始 bytes 直接複製進來，僅放入已驗收的新 slot，main/tab 沿用下載備份。以標準 ZIP 封裝這份最終清單，再用隨附 `validate_pack.py --help` 所示入口驗規格；16 張包應為 18 個根目錄 PNG。此包標記為 `remote-final`，和本機重新 render/build 的候選包分開。備份保留舊檔、新來源、修正專案、最終清單與逐檔 hash；不可把會重畫其他圖片的 build 包稱為後台原樣備份。

## 容易誤讀的瀏覽器狀態

- snapshot 的 image 是語意角色，未必是 HTML img。`img` 查詢為空時，先檢查該區域 DOM；LINE 圖片清單可能使用 `input[type=image]`／`[data-test=product-image]`，標籤清單才使用 img。只取本次實際觀察的 src，不猜 URL。
- `goto` 或 networkidle 不一定代表資料已填入；等待作品 ID、張數、圖片或標籤名稱等可觀察條件。空清單時停下調查，不能直接繼續下載／加工或把空值記作無內容。
- 推薦標籤可能與用途不符。依文字、動作和聊天情境從實際目錄選 ID；先小量測試，再整批寫入，完整流程見 line-upload。
- 勾選後可能延遲儲存。當下勾選、固定等待秒數、迴圈完成均不能證明保存；離開後重新讀回所有 slot 與 ID 配對，缺項才補。上限是最多可選數，不是應填滿的數量。
- 同頁 `Update Request` 和 `Product Details` 是不同版本。分區讀狀態與標籤，空的可編輯標籤不代表沒有平台自動標籤。原版販售中可與更新等待審核並存。
- 確認視窗可能延後出現；查看可見且 aria-modal=true 的對話框。勾同意並按 OK 後，等待平台狀態再記 submitted。超時重讀原作品，禁止盲目重送。
- 送審前確認自動／手動發布或更新；成功訊息與等待審核不等於核准、更新已生效或已開始販售。

## 完成與複盤

保存最終狀態快照、配對與標籤證據；回報送審／核准／販售分開。複盤寫入作品紀錄，只有可重現且可泛用的規則才進技能。個別帳號、作品 ID、未證實原因和競品素材不寫進通用流程。
