# 主題美術系統與場景驗收

製作或改進主題前讀本文件，再讀 emoji-theme 核對技術規格。主題是一整套介面：背景、文字可讀性、圖示、選取狀態、密碼與頭像應共同傳達同一情境，不把貼圖加白邊後放在單色底當成完成。

製作與修改均須依 [主題送審關卡](theme-release-checks.md) 執行直橫向、壓縮後角色色彩及深底功能細節檢查；將結果綁定最終成品 hash。

## 先研究，再定方向

需要熱門研究時，查看 5–10 個實際商品頁及完整預覽，包含有知名 IP 與無大型 IP 的樣本。記錄榜單分類、地區、時間、當次位置、商品連結及裝置預覽。熱門頁排序不等於公開下載數；曝光、IP、檔期、售價、上架時間都可能影響表現。將「看得到的設計」和「可能受歡迎的原因」分欄，不作因果結論。

每例觀察：主底色／輔色／重點色、圖案密度、聊天有字與無字、角色位置與場景行為、導覽／輸入欄是否延伸道具、圖示尺度與 ON/OFF、密碼與頭像、其他裝置差異。商品頁只顯示某個選取狀態時，標註未見完整 ON/OFF，不推測所有資產。競品只學配色關係、構圖和資訊層級，不搬用角色、構圖、圖示或原圖進交付包。

## 美術契約

每套先寫 `art-direction.json`，定義：

- `story`：角色在何時何地做什麼，至少一個具體活動與角色／道具關係。
- `styleFamily`：例如扁平生活場景、低飽和編輯插畫、微紋理圖案；同 IP 的新套組在場景、構圖、材質或形狀語言上有實質差異，不只換底色。
- `palette`：surface、background、text、muted、accent、selected、unselected 的色值與用途。先選主底、輔色、少量強調色；顏色數量按畫風決定，避免每個圖示各自選色。此為工作配色，不保證後台每個系統色都可自訂。
- `edges`：預設取消貼紙式粗白邊，採同色系深描線、實心塊面或柔和輪廓。白色角色本體及必要對比不等於白邊。iOS 26 圖示仍需在黑／白底辨識，不能為了無白邊犧牲功能。
- `iconSystem`：共同視覺重心、光學尺寸、線寬、圓角、陰影與基線。功能語意先行，再加入世界觀道具；避免整排都變成難辨功能的角色頭。
- `states`：同一位置與尺度的 OFF/ON，至少有清楚色塊／填色／形狀差異，不只改極細線條。不把 LINE 通知點畫進圖。
- `sceneLayout`：敘事焦點、訊息安靜區、輸入欄遮擋區、縱橫裁切與背景延伸色。

## 背景與介面如何一起安排

場景型：先設地面／桌面等支撐、前中後層與光源，再放角色及有用途的道具。角色不必很大，但活動應可辨識。把場景道具選擇性轉成密碼狀態、導覽與頭像細節，形成連續世界觀。

簡約型：可以沒有完整透視場景，但需要清楚母題、留白節奏與穩定色彩；例如邊緣花帶、少量紋樣或幾何節奏，不能只換色複製同一坐姿。情境需求明確時優先場景型。

聊天區：以低對比背景／疏密控制讓訊息優先，不僅檢查空白壁紙。不要強制所有作品把角色放底部固定百分比；依實際裝置與對話覆蓋調整。背景靠中下對齊，Android 輸入欄會蓋住下方，重要臉／手／道具必須在實際預覽中可見。大螢幕露出的背景色要與圖上緣協調。

導覽區：按可見圖形的光學尺寸對齊，不只把 PNG 方框置中。比較每個 ON/OFF、通知點覆蓋、文字標籤和 iOS 26 橫向畫面；舊版選單留白依官方規格。連續背景要兩端可銜接。不同裝置會使用不同框架與系統圖示，不承諾重畫整個 LINE 介面。

## 先驗代表畫面，再展開全套

先完成聊天有訊息／無訊息、主頁及一組導覽 ON/OFF 的代表畫面，確認美術方向後才延伸全套。既有授權足夠時由代理完成方向驗收；使用者要求先看時停在預覽供其選擇。

最終 `visual-review.json` 逐項記 observed、verdict、evidencePath、assetHash：

| 關卡 | 判斷 |
|---|---|
| 敘事 | 可描述角色正在做什麼，場景和道具有關聯；簡約型則有明確母題 |
| 整體協調 | 各頁共用配色角色，主圖與實際介面一致，風格不突然變成另一套 |
| 訊息閱讀 | 有／無對話、長短訊息、時間與輸入欄均清楚；細節不和文字爭焦 |
| 邊緣 | 沒有非設計所需的粗白框、殘留白底、半透明光暈；黑白底檢查 |
| 圖示功能 | 縮小後可辨、視覺重心／基線一致、ON/OFF 清楚，通知點不遮核心 |
| 跨裝置 | iOS 26、舊 iOS、Android，直／橫向與大小螢幕的裁切、輸入欄遮擋有證據 |
| 其他畫面 | 密碼四位置狀態、圓形／方形頭像、三張主要圖均實際看過 |

若平台只提供部分預覽，明列未測範圍；用標示為模擬的覆蓋圖補檢，不把模擬叫真機。技術合格但任何必要美術項 rework 時不得送審。改來源／色彩／裁切後重驗受影響畫面。

官方規格：https://creator.line.me/zh-hant/guideline/theme/detail/ 。每次製作重新核對；主題研究中的好看是設計判斷，不能承諾銷量。
