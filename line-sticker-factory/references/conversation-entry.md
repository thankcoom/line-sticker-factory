# 對話入口：先有角色，再做作品

這是分享版的新人引導與接續契約。第一輪先辨認當次工具能力及使用者階段；沿用已知答案，不讓熟悉需求的使用者重走問卷。

## 入口選擇

先簡短說明可以一起設計角色或使用既有角色。主要選擇：A 已有角色、B 從零設計、C 接續作品。每次只處理一個主要決定，通常提供 2–3 個有差異的選項，並允許自由描述、混合或全部重提。

當次確實有適用的選項／使用者輸入工具才使用它。圖片需使用者附檔時，在一般對話請其附圖，不透過僅支援文字的選項工具索取上傳。沒有互動工具就列 A/B/C，讓使用者回覆字母或自己的想法；不要稱為已建立可點按鈕。技能文件不會憑空新增 ChatGPT UI 元件。

能力分開記錄：可讀檔、可生圖、可取得圖片原檔、可加工、可操作瀏覽器。一般 ChatGPT 讀到上傳技能不等於永久安裝，也不等於能操作使用者本機。缺工具只停止依賴該工具的階段，其餘討論可繼續；不自行改計費服務。

## B：沒有角色

依已知資料縮短輪次，不必每輪都重新確認全部設定。

1. **用途與個性。** 先問這個角色主要替誰說話、想傳達什麼個性。若完全沒想法，可給日常陪伴、上班吐槽、溫柔鼓勵等少量用途方向；下一輪再問角色個性。記錄使用者語氣及不喜歡的元素。
2. **原創角色方向。** 根據前一輪提出 2–3 個有區別的角色概念，每個包含暫名、物種／類型、性格及一個辨識特徵。這時是文字提案，不是假裝已產圖。不把知名 IP 當成使用者自己的角色。
3. **外型與畫風。** 選中概念後，討論輪廓、比例、五官、配色與服裝；再選畫風。角色身分參考與畫風參考分開。使用者可混合概念或要求重提，保留已接受的決定。
4. **生成候選。** 確認足以執行的設計後，用實際可用生圖工具產生第一個候選角色；一次派送一項任務、保留提示詞與來源。使用者要求比較時再做有限個候選，不直接生成 40 張。候選需看得清五官、身體比例及代表配色；沒有背面資料就標未定，不假裝三視圖已齊。
5. **展示與修訂。** 展示實際候選圖，選項為沿用／局部修改／換方向；用可辨識的候選編號。未獲接受都標候選。局部修改明列保留與改動範圍，改完重新查看；不承諾模型完全不改其他部位。
6. **角色確認。** 使用者接受具體圖片後建立角色設定卡，記已確認身分參考、不可變特徵及尚未定義部位。只有文字設定已同意時仍是 design_approved；圖已接受但原檔無法取得時為 image_approved_awaiting_asset。原檔可解碼才可記 ready_for_production。
7. **轉入貼圖。** 帶著已選角色討論聊天對象、用途與語氣；再確認產品、張數與文字策略。呈現首批八張劇本，包含台詞、動作、聊天用途與差異，取得計畫接受後再生成。使用者先前已給完整指令時直接沿用，不重問。

## A：已有角色

從本次附圖及使用者自己的角色庫列出實際可用角色，最多先展示少量候選，必要時分頁。每個選項包含穩定 ID、名稱、圖片／可定位的附件及來源；同名用編號區分。只有一個角色時先確認沿用，無需製造假選項。

空角色庫不是故障：請使用者附原圖，或轉 B。名稱／歷史縮圖不足以代表已取得原始身分圖；標 awaiting_asset，取得原圖再加工。分享包不附原持有者的私人角色，也不預設使用別人的作者名稱、版權或帳號。

選定後整理角色的眼型、五官、比例、配色、服裝與個性，請使用者確認任何不確定之處，再保存角色設定卡。畫風圖只影響畫法，不替換角色身分。然後轉入 B 第 7 步。

## C：接續作品

讀取使用者交付的進度、角色設定卡、原圖和作品備份。先顯示選中角色、目前階段、已接受決定及下一件未完成事項；不要重新跑全問卷。作品檔仍用 CLI status／restore，不用本文件的紀錄覆蓋 project.json。

## 進度保存與跨對話接續

有檔案工具時，在使用者工作目錄（技能資料夾之外）保存 `conversation-state.json` 與 `character-card.md`；沒有檔案工具時提供可複製的同等內容，誠實標示未保存成檔。只有取得可解碼原檔才寫實際路徑及 SHA-256，否則寫附件識別或 null，不捏造本機路徑。

conversation-state 至少包含：schemaVersion、stage、capabilities、selectedCharacterId、candidates（id/name/status/reference）、acceptedDecisions、pendingQuestion、nextAction、characterCard、projectPath。stage 使用 discovery、character_directions、character_visual、character_review、sticker_brief、sticker_plan、production、review、delivery；候選狀態與來源取得狀態另外保存，不用 stage 假裝已生成。

角色設定卡至少包含：角色 ID／名稱、用途與個性、已接受參考及來源、不可變特徵（眼型／五官／比例／色彩／服裝）、可變表情與動作、獨立風格參考、尚未定義部位、確認依據、原圖取得狀態。權利資訊只有使用者提供才能填寫；角色被選中不等於商標或著作權查核通過。

跨對話交接提供角色卡、conversation-state、生成紀錄、可取得原圖及作品備份的實際檔案；沒有檔案就列清楚待補項。記錄只含製作需求，不含密碼、cookie、token 或帳號登入資料。

## 停止與繼續的判斷

- 未選定角色：繼續討論／候選，不量產貼圖。
- 無生圖工具：完成設計及提示詞，標待生成。
- 原檔未取得：可討論劇本，但不能宣稱已裁切、加工或打包。
- 額度不足／結果不明：保存並核對現有產物，停止新派送。
- 已有完整角色與計畫：跳過已回答輪次，直接執行授權範圍。
- 沒有瀏覽器／帳號：可交付本機圖片包；上傳另列待辦，不假稱已上傳。
