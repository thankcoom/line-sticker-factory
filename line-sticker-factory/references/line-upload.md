# 使用 ego-browser 上傳

上傳前先完成 [每套上架前檢查](release-preflight.md)。退回修正、局部換圖、空圖片查詢與販售／更新雙版本的處理也在該文件；保存對應版本的證據。

只有使用者要求上傳／上架才開始；製作或安裝技能本身不觸發帳號變更。已有授權沿用，不反覆確認。送審、定價、公開販售依使用者明確指示與現有帳號設定處理；未提供會影響權益的必要值才問。

1. 先執行 `ego-browser skill` 並讀到結尾，遵循當前版本 API。用真實 browser 命令測試連線；不把舊對話的連線錯誤當作現況。必要時讀當次可用 ego-browser 技能。只看見指令存在不等於連線成功。
2. 在同一 TaskSpace 操作。讀現有分頁／作品清單，確認目標帳號及登入。使用使用者給的 URL 或實際觀察到的連結；不把包裝者的個人帳號寫成通用預設。不要索取 cookie/token。登入、驗證碼或瀏覽器權限提示由使用者處理。
3. 先檢查是否已存在同名／同素材草稿，再建立或續傳，避免重試產生重複作品。填名稱、說明、作者及版權等必要資料；值必須有來源，不能猜帳戶資料。未核對平台標籤 ID 的建議關鍵字不能宣稱已套用。
   參加活動時，先唯讀核對當期官方公告和後台選項：居住地／新作品資格、至少相關張數、最低價格、送審截止與時區、最晚開賣日、特殊授權／AI 限制。記錄來源 URL、查核時間與衝突；日期矛盾不能靜默當作已確認。填妥後確認活動實際被選中；名稱含活動主題不等於報名成功。
4. 靜態貼圖上傳前用本技能 validate 檢查最新版本；表情貼／主題依 [各自契約](emoji-theme.md) 核對素材清單與驗收。上傳 line-upload.zip，不是包含三檔的外層交付包，也不是 project-backup.zip。依實際頁面支援使用 setInputFiles／file chooser。每次動作後看真實結果。
   若剛變更貼圖張數（例如 8 改 40），先完成確認／儲存，等待可觀察的完成狀態，再重新載入頁面，確認張數欄位仍為目標值，才上傳相應 ZIP。DOM 暫時展開 01–40 不代表張數已持久化。若收到「ZIP檔案中所含的圖片數量與貼圖張數欄位所填寫的數量不符」，先重新讀取同一作品的張數及每格已保存圖片，記錄可能的部分成功；張數確認持久化後才在原作品重試。不能因錯誤就重建作品、當成全部失敗，或將只成功前 8 張說成 40 張完成。
5. 讀取後台作品 ID、URL、圖片數、main/tab 與每個 slot 的配對，核對缺漏和錯序並查看圖片。保存作品旁 listing-state.json：itemId、url、accountEvidence、projectRevision、uploadZipSha256、status、uploadedSlots、imageMappingEvidence、checkedAt、errors。證據可為實際截圖路徑與可定位的頁面狀態；只記點擊成功不算上傳成功。
6. 狀態分 prepared_not_uploaded、draft、uploaded、submitted、approved、on_sale，以頁面實際顯示為準。超時或結果不明先重讀既有作品，不重複建立／提交。技能驗證通過不代表使用者作品已上傳。
   等待審核是平台待處理狀態；自動流程不能略過審核或假稱已販售。若已授權公開販售且頁面已核准，才接續發布並驗證 on_sale；手動發布設定須記錄為尚待處理。按儲存或切換標籤後要等持久化結果，必要時重新載入核對，不以按鍵回執或短暫勾選狀態當證據。
7. 整個使用者目標的瀏覽器工作完成後依當前 ego 指引 finish，不在同一目標的中間作品完成時提早結束 TaskSpace；需要使用者接手則 handOff。回報真實作品連結及目前狀態。

平台規格可能改變，上傳時核對官方頁面 https://creator.line.me/zh-hant/guideline/sticker/ 與後台提示。隨附加工器目前支援靜態 8/16/24/32/40 張、貼圖最大 370×320、main 240×240、tab 96×74；平台規格若與加工器不同先停下說明，不能偽造通過。

## 最終確認中的額外訂閱

送審授權不包含優惠／行銷通知訂閱。每次提交前，列舉當前有效確認視窗及關聯表單的全部勾選項，包含 snapshot 未顯示但可能隨提交生效的 DOM 控制項；預設取消未明確授權的優惠通知，勾選有來源與授權依據的必要同意，立即讀回兩者狀態再按 OK。預勾或 required 屬性不是額外授權。完整判斷與證據欄位見 [主題送審關卡](theme-release-checks.md) 第 5 節；不改動無關帳號偏好。

## 逐張標籤與延遲儲存

需要標籤時，從當前平台讀取實際可選標籤與 ID，再按每張的聊天用途配對。先以少量圖片確認「勾選 → 寫入完成 → 離開再讀回」成立，才擴大到整套。標籤頁可能延遲自動儲存；勾選數增加或當下 networkidle 都不能單獨證明寫入完成。若快速換張後標籤消失，先回讀既有作品的逐張狀態，在原作品補足缺項，調整等待方式並重驗，不重建作品。

整套完成後重新載入標籤總覽，以每個 slot 的實際已存標籤比對計畫，保存逐張名稱／ID 與讀回證據。只有全部相符才記錄 tagsVerified；點擊回執及腳本迴圈完成不算保存成功。平台延遲可能改變，不把一次成功的固定等待秒數寫成通用保證。
