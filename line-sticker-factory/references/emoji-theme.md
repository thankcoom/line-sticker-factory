# 靜態表情貼與主題

這兩類使用代理製作流程，`sticker_project.py` 不支援它們。保留原圖、提示、裁切座標和驗收證據，利用 Pillow 等確定性加工做尺寸、alpha 合成檢查與 ZIP；視覺生成／修正仍用當次可用生圖工具，不用程式繪改角色。規格以下為 2026-11-16 實際核對，製作新作時再核對官方與後台。

## 共用製作紀錄

作品目錄包含 production-plan.json、generation-ledger.json、render-manifest.json、rendered/、visual-review.json、build-result.json、listing-state.json。每張 render-manifest 紀錄 file、source、sourceHash、crop（明確說明 xyxy 或 xywh）、size、sha256、review、reason；實際看過才能標 pass。來源、裁切、尺寸或像素改動，受影響成品改為 pending，再看最終尺寸。所有驗收通過才能正式打包／送審；可將候選圖上傳既有草稿以檢查平台預覽，須標為 draft-preview，不宣稱最終通過。

原圖預覽出現底色時，先讀 alpha 並合成白／深底。alpha=0 區的 RGB 可有顏色，不構成可見背景。半透明光暈須以合成結果判斷，不能只看原始預覽就重生。各畫布尺寸不固定，依實際透明間隔決定裁切；鄰格無法分離時修整張畫布間距。

選單先設計辨識功能的圖案，再加 IP 特徵；OFF/ON 有明確色彩或形狀差異，縮小後仍辨識。iOS26 圖示在白／黑背景皆清楚。通知紅點由 LINE 加入，不畫進成品：iOS26 右上32×32；舊規格33×33、上49px右21px。以模擬覆蓋檢查核心圖意，不要求所有圖案完全避開紅點。

聊天圖靠中下對齊；Android 下方會被輸入欄覆蓋，保留安全距離。中心留給訊息，背景色與配色吻合；檢查有對話／無對話，以及三種裝置預覽。圓形頭像、密碼所有位置、主要圖也逐張查看。後台選單是預設配色方案加可指定的聊天背景色，不能承諾任意修改全部介面顏色。

上傳後進入「下一步」選顏色排版，保存後重新進入配色頁驗證方案、背景色和勾選狀態。預覽可能是 canvas 而非 img。若 toDataURL 出現 tainted canvas，改用頁面截圖；可記錄 DOM 邊界裁出各預覽，不反覆嘗試匯出受限畫布。保留 iOS26、iOS、Android 的預覽證據。全地區主題最低價當時為 NT$90，製作時讀後台，不把它寫死為永遠價格。

## 圖片配對、交付與還原

從實際 DOM 取得每個圖片 URL 與 slot，不能猜 URL。需登入的圖片使用 page.fetch；公開 CDN 可用一般 fetch。先比檔案 SHA256；若 CDN 重編碼導致 bytes 不同，解碼為 RGBA，確認尺寸及四個通道逐像素完全相同。Pillow 的 RGBA difference.getbbox() 單獨可能忽略 RGB 差異；應確認每個通道 extrema 均為 (0,0)。若像素也不同，保存差異並重新看圖，不把尺寸相同當圖片一致。

上傳包只含素材清單的根目錄 PNG，總覽使用實際加工圖／平台預覽。備份含完整來源、計畫、裁切與檔案清單、每張驗收、已渲染 PNG、提示與進度；排除 exports 和 restore 目錄以免遞迴。解壓到新目錄，逐張比對渲染 PNG hash，確認所有來源可解碼。上傳包建立後再修改成品必須另建版本並重驗。送審依 [上傳流程](line-upload.md)，既有授權可沿用；等待審核不等於已販售。
