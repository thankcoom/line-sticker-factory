# 畫布檢驗與局部修正

每次生成或編輯後，由代理實際看圖完成第一輪檢驗；這是視覺判讀流程，不是已實作的 OCR／肢體偵測器，也不保證零漏判。CLI 的技術驗證與人工／代理視覺驗收分開記錄。

## 先記錄修正合約

在動手前分出：使用者接受的部分、指出的缺陷、這次可變部分。原圖作為 edit target，角色圖作 identity reference，兩者角色不同。使用者說尾巴接錯，不等於同意把角色移到門外、換姿勢或換整套風格。

八格畫布修正提示採這個順序：

1. 指定畫布版本、欄列、目標格號與位置。
2. 保留目標格的角色、台詞、情境、鏡頭及道具遮擋關係。
3. 描述要改的局部，以及修好後能看見的連接關係。
4. 保留其餘七格的角色、文字、位置、尺寸與留白；不新增編號或分隔線。
5. 完整畫布透明輸出；重新檢查全部八格，因模型可能同時改動非目標格。

例：右上格保留從門內探頭的情境、門牌文字和門框位置。只修尾巴：尾根從角色骨盆後側伸出，先被身體／門板合理遮擋，再連續出現在右側；不能成為獨立道具，也不能穿過門板。其餘七格保持原樣。

若同一缺陷連續兩次修正仍失敗，先比對版本與提示的歧義，再縮小修正範圍；不能無限重派、悄悄換文字或把合圖拆為單張。使用者原話或已核准台詞需要更改時，保留原要求並標示替代方案，而不是將錯字合理化。

## 逐格檢查順序

| 檢查 | 判讀方法 | 不通過時 |
|---|---|---|
| 角色身分 | 對照原始身分圖的頭身比、眼睛、耳朵、額紋、口鼻、毛色、尾巴特徵；表情可變，身分特徵保留 | 記錄具體漂移，修該格 |
| 身體連接 | 從頭頸到軀幹、肩到手、骨盆到腿／尾根逐段追蹤；數肢體，說清楚遮擋前後順序 | 接點不明、斷裂、穿插或多肢都標 rework；可遮擋，不必強迫全身露出 |
| 手與道具 | 手抓住哪一面、袖口來自何處、支撐點與受力方向是否合理；門、衣袖不能變成人體的一部分 | 修局部接觸與遮擋，保留情境 |
| 文字 | 逐字對照計畫，檢查漏字、同音字、繁簡、標點、字序；特別看「准／準」等形近字 | 不以看起來差不多通過；文字融入原圖者透過生圖修正 |
| 情境用途 | 能指出一個收訊對象、觸發情境與被替代的自然口語；動作與語氣一致 | 補具體情境或調整台詞，避免只有好看卻不知道何時傳 |
| 格間與裁切 | 按真實像素與 alpha 透明間隔檢查格序、邊界留白、跨格內容、耳尾字的完整性；八格布局不代表內容恰好落在八個等分矩形 | 逐格校正 crop，確認整個目標保留且沒有鄰格碎片；不能裁掉問題來假裝通過 |
| 透明與邊緣 | 查看 alpha，並將同一 RGBA 圖分別合成白底與深底觀察；0 alpha 像素中的 RGB 顏色不等於可見背景 | 修可見光暈／殘影；不要因隱藏 RGB 預覽顏色盲目去背 |
| 最終尺寸 | 查看加工後 370×320 以內圖、240×240 main、96×74 tab；以實際顯示大小看字與輪廓，不只看放大的原圖 | 修排版／選適合來源；縮小後讀不到就不能通過 |

## 檢驗紀錄與關卡

### 眼型與表情的身分檢查

當角色有明確眼型參考，或使用者指出眼睛漂移時，每格 `identity` 之外另填 `eyeStyle`：`referenceStructure`（原型眼白／瞳孔／眼框結構）、`observedStructure`（本格實際結構）、`expressionChange`（眼瞼、閉眼、視線等表情變化）、`verdict` 與短證據。逐格對照原型，不能用整批「五官有誇張」代替判定。

例如原型為實心黑點眼：半瞇或閉眼線可保留原本結構；突然長出大片白色眼球、獨立上翻瞳孔則是身分漂移，須回修。此例只適用該眼型，不能把其他 IP 的白眼球一律判錯，也不能將已接受的半瞇眼全部改成黑圓點。使用者圈定某格時，沿用原畫布只修指定部位，其他格重新比較但不擴大重做。

裁切先把等分網格當定位起點，再依各格實際 alpha 輪廓與透明間隔決定邊界。上下格的腳、尾巴或橫幅可能超過名義分界，左右欄也可能需要不同的橫切位置；不要固定使用 512×384 等分後直接驗收。每個 crop 都查看完整角色、文字和道具，以及四邊是否帶入鄰格碎片。若相鄰內容真的接觸／重疊、沒有能保全兩者的透明分界，回到畫布修間距，不以裁斷肢體／文字或抹除來源來處理。alpha 只能輔助找邊界，不能分辨哪個愛心、字或腳屬於哪張，仍須實際看圖確認。

在作品旁保存 visual-qa.json，逐格記錄 canvasId、sourceHash、slot、expectedCaption、observedCaption、identity、anatomy、occlusion、useCase、crop、alphaWhite、alphaDark、finalSize、verdict、issues、evidencePaths、reviewedAt。每項以 pass／rework／not_checked 搭配短證據說明；不明項目保持 not_checked。

畫布看過不等於最終成品看過。畫布通過後匯入、render、preview，再查看最終尺寸，全部相關項目通過才由 CLI `review --status pass` 記錄。合圖更新後，用新來源 hash 重新匯入受影響 slot；其他格也比較新舊輸出，不能沿用已失效的驗收。送審前 build／validate 只使用最新有效版本。

複盤保存於該作品的工作紀錄：缺陷、哪次檢查漏掉、最小有效修正、證據與可重用規則。只把已證實且可泛用的規則更新到技能；不把作品敘事、未證實原因或個人帳號資料寫進通用技能，也不擅自寫入個人記憶。

## 尾巴專項與漏判回修

每隻角色逐一確認一個尾根、一條連續尾身、一個尾尖。沿骨盆／臀部追到尾尖，尤其檢查腳下環繞長條：若兩個可見端都像深色尾尖，或無法指出哪端接回身體，必須標 rework，不能以可愛、對稱或可能遮擋推定合理。驗收證據要說明尾根位置、轉彎方向、唯一尾尖位置及遮擋；不能複製「肢體正常」作為逐張證據。

使用者指出已通過的缺陷時，承認漏判、保留舊驗收與檔案、將該格改為 rework。若已送審且仍可撤回，依現有授權撤回修正；不能把舊待審當成修正完成。於原畫布修正，重新查看最終尺寸白底／深底，再更新來源、驗收、交付包和後台圖片配對證據。
