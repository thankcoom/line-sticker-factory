# 每套主題的製作、驗收與送審關卡

每次主題製作或修改都由代理主動依序執行，不等使用者提醒。這是既有工具檢查、代理看圖與瀏覽器讀回的工作流程；不是背景排程，也不是已實作的全自動美感或膚色判錯器。只使用當次可用工具，不切換計費來源。

## 1. 先驗背景在不同方向的構圖

製作代表背景時，同時檢查直式與橫式，通過後才展開交付。依當期官方規格和後台實際顯示位置，模擬靠中下對齊、較窄／較寬螢幕及輸入欄遮擋；記錄 viewport、縮放比例、對齊方式和遮擋高度，不能固定套用某次作品的像素座標。

- 橫向看左右場景是否連續、突然露出純色邊帶／硬接縫，以及臉、手、道具、腳是否被裁掉。
- 大螢幕看上緣露出的指定背景色是否自然；直向看核心行為是否留在安全裁切區。
- 看有／無訊息的畫面：氣泡、時間、輸入欄可讀；聊天訊息自然覆蓋裝飾不等於裁切錯誤。
- 發現場景缺邊時，用生圖工具擴展左右場景，保留已批准角色與中央構圖；重新查看生成結果，不能假定擴圖沒有改掉眼型或肢體。不拉伸人物，也不以不協調色帶假裝完成。
- 只有已確認平台未提供該預覽時才用模擬補檢；尚未載入、讀取失敗或未取得畫面仍是 pending，不能用模擬代替現有平台預覽。後台沒有橫向預覽時，保存明確標示「模擬」的檢查圖，並明列未做真機測試。

主頁及密碼頁能否自訂全幅背景，以當期後台欄位為準。代表稿先說清楚平台限制；不要把無法實現的概念頁當成已完成資產。

## 2. 壓縮後另做角色色彩驗收

容量合格不是色彩合格。PNG 調色盤量化可能把背景占比高的作品之膚色、灰色側髮、眼點與細線合併，造成斑塊、斷線、色帶或抖色雜點。

1. 保留無損來源；記錄縮放、量化方法、調色盤、抖色設定與最終成品 hash。
2. 對照來源及壓縮結果，查看最終顯示尺寸與臉／眼／手／腿局部放大圖；透明素材另合成白、黑及實際介面底色。不是只看壓縮前原圖。
3. 有劣化時先比較可用的無損最佳化或合理縮放。仍需索引色時，可為角色重要色階保留調色盤配額，再分配背景色；比較關閉抖色的結果。配額與選區依本作品決定，不把某次的 192／64 色或人物座標寫成固定規格。
4. 調色盤模式須符合當期平台要求；保留透明度，不因壓縮把透明圖轉成不透明。Indexed PNG 轉回 RGB 可能重新放大容量，最後必須重驗實際輸出檔。
5. 重新看圖後才記 pass。容量、尺寸或平均誤差都不能自動判定膚色與眼型正確。

## 3. 深底功能圖示逐對檢查

每組 OFF／ON 都以最終尺寸放在白、純黑及實際介面底色上查看，再補通知點覆蓋和橫向標籤排列模擬。檢查提把、輪廓、孔洞、播放三角、扣件等辨識功能的細節，不只看整體有色塊。

深描線融入深底時，調整該功能部件的填色／輪廓對比，維持同組尺度與造型；不以粗白邊一律補救。只替換有問題的資產，其他資產以 hash 證明保留。通知圖標只存在檢查圖，不烘焙到上傳 PNG。

## 4. 後台完成載入後才驗收

networkidle 超時可能是無關帳號請求；改等作品 ID、完整圖片欄位和實際內容等可觀察條件。canvas 數量出齊不代表繪製完成；先辨認目前顯示的是已選方案還是載入中 placeholder。保存並離開再進，讀回方案、指定背景色與勾選狀態，再截取實際完成的預覽。不以固定秒數、某個固定 canvas 數量或一律要求名稱不含 default 代替狀態判斷。

完整看過當期後台提供的 iOS 26、舊 iOS、Android 主頁、無／有訊息聊天、密碼畫面。保留平台預覽與模擬的區別。從 DOM 取得本次圖片 URL，重新下載全部最終素材，比 bytes hash；重編碼則比較尺寸及 RGBA 四通道逐像素結果。

## 5. 送審對話框排除額外訂閱

沿用使用者已授權的送審，不重問同一許可。送出最終確認前，檢查當前作品的有效確認對話框及其關聯表單，列舉所有勾選項的文字與 checked 狀態；snapshot 未顯示的項目仍可能存在於 DOM 並隨提交生效。不要碰其他隱藏舊對話框或全域帳號偏好。

- 將必要的著作權／送審同意，與優惠、行銷、限定通知等選填同意分開。
- 本流程預設取消該次提交的優惠／行銷通知；只有使用者明確要求此類訂閱才保留。預勾狀態或 required 屬性本身不代表使用者授權，也不能證明它是必要送審條款。
- 依已確認的角色來源與授權勾選必要同意；不虛構版權事實。
- 操作後立即重新讀回全部勾選狀態，確認必要同意為 true、未授權的額外訂閱為 false，再按最終 OK。若通知不存在，記錄已查核及 absent；absent 記在 observed，完整查核後 verdict 才能為 pass；如果其語意或取消方式仍不明，暫不提交，先查清，不繞過核准攔截。
- 自動核准因額外訂閱拒絕提交時，先取消該選項並取得讀回證據，再重試已授權的送審。禁止換工具繞過仍未解決的拒絕。

## 紀錄與提交門檻

這些是代理必須執行的檢查與紀錄契約，尚無獨立程式會強制攔截提交；不得宣稱已新增無人值守自動 gate。

在 `release-preflight.json` 增加 `themeChecks`，每項都記 `verdict`（pending／rework／pass）、`observed`、`evidencePath`、`assetHashes`；涉及來源對照時另記 sourceHash。至少包含：

| 欄位 | 必要證據 |
|---|---|
| landscapeBackground | 直橫向、大小螢幕、對齊與遮擋參數、角色安全區及接縫檢查 |
| compressionColor | 實際壓縮設定、容量、來源與成品局部比較、眼點及膚色判斷；未使用有損量化也要查看最終成品 |
| darkIcons | 全部 OFF／ON 的白黑實際底色、小尺寸、通知點及標籤排列 |
| platformPreview | 重新讀回配色、完成載入的三平台預覽；缺少平台預覽時列範圍與模擬補檢 |
| submissionConsent | 當前作品 ID、查核時間、各項 label／checked／用途、通知 absent 或 false 的證據；明確訂閱授權才可 true |

前四項在最終確認前完成；submissionConsent 在當次確認視窗開啟後、最後 OK 前完成，不能從過去作品複製。所有必要項 pass、逐張驗收 hash 對應現在成品、後台配對通過、blockers 為空且已有送審授權才提交。有問題先修正受影響資產並重新上傳、驗收、配對；不可把其他資產的 pass 套用到新版本。

提交後讀回同一作品的實際狀態，保存 `listing-state.json`、截圖及最終交付／備份。等待審核、核准、販售是不同狀態；結果不明先讀回原作品，不盲目重送。
